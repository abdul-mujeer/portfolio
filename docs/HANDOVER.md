## 3. How to run everything (from a clean clone)

```powershell
# Portfolio site
npm install; npm run build; npm run verify:site

# Each QA project (example: ShopSure; the others follow the same shape)
cd projects/shopsure-qa
npm install
npm run db:reset          # deterministic synthetic seed data
npm start                 # http://127.0.0.1:4100 (PeopleCore 4200, TaskFlow 4300)
npm run test:all          # every suite + generated execution report
```

## 6. Known limitations (aggregated)

- **Browsers:** UI automation runs on Chromium only; Firefox and WebKit are not installed in this environment.
- **Concurrency:** the demo databases are single-writer SQLite files, so parallel-write scenarios are not covered.
- **Accessibility:** targeted smoke checks (labels, skip link, alert regions, alt text, mobile viewport) — not a full WCAG audit, and no screen-reader pass.
- **Performance:** PeopleCore and TaskFlow include local autocannon baselines; they are single-machine indicators, not capacity planning.
- **Security:** checks cover injection, mass assignment, authorization boundaries and cookie/header hygiene; no professional penetration test was performed.
- **Exploratory sessions** are recorded as evidence files; they do not replace a human tester's judgement.
- **Linting:** the PeopleCore and TaskFlow ESLint configs exclude their TypeScript Playwright specs (no TypeScript parser in their dependency sets); this is documented in each README.
